# 최순호 · Choi Soon Ho

GitHub Pages에서 제공하는 한·영 포트폴리오입니다. 방문자에게는 완성된 HTML과 PDF를 제공하며, 프레임워크나 실시간 데이터 요청은 사용하지 않습니다.

## 어디를 수정하나요?

| 수정할 내용 | 원본 |
| --- | --- |
| 이름, 직함, 소개, 이메일, 외부 링크 | `data/portfolio.json` → `profile` |
| 홈·CV의 현재 활동 요약 | `currentRoles` |
| 학위, 자격 | `education`, `qualifications` |
| 강의 기관, 과정 설명, 역할 | `organizations`, `courses`, `roles` |
| 강의 기간과 기관·과정·역할 연결 | `teaching` |
| 연구활동 주제 태그, 논문, 저자, 학회 | `researchTopics`, `papers` (`topics` 포함), `authors`, `venues` |
| 메뉴, 제목, 버튼, 접근성 안내, PDF 표 제목 | `locales/ko.json`, `locales/en.json` |
| 최종 내용 갱신일 | `data/portfolio.json` → `updated` |
| 전체 페이지 배치 | `src/index.template.html` |
| 공유 색상·글자 크기·간격·열 비율 | `data/design.json`, `scripts/design.py` |
| 웹 배치·반응형 규칙 | `assets/site.css` |

같은 사실을 웹과 CV용으로 두 번 적지 않습니다. 홈의 요약, 상세 탭, PDF가 같은 레코드를 사용합니다. `index.html`과 PDF는 생성 결과이므로 직접 편집하지 않습니다.

연구활동 제목 옆의 `researchTopics`는 전체 연구 관심 분야를, 논문별 `topics`는 실제 논문 제목·본문에서 확인되는 주제를 연구자에게 통용되는 한·영 학술 용어로 기록합니다. 홈·연구활동 탭·CV가 같은 태그를 사용합니다. 별도의 연구 관심사 화면은 표시하지 않으며 기존 관심사 원본은 보존합니다. CV는 넓은 현재 활동 열과 학위·자격 열을 나란히 배치하고, 연구활동과 경력은 전체 너비에 표시합니다.

## 학습 자료

경력 탭의 **학습 자료**에서 인터랙티브 개념 지도로 이동할 수 있습니다.

- 공개 주소: <https://snow0821.github.io/learn/prompt-engineering/>
- 내용과 동작: `learn/prompt-engineering/index.html`을 직접 편집합니다. 별도 빌드나 외부 스크립트 없이 동작하는 정적 페이지입니다.
- 포트폴리오의 연결 위치: `src/index.template.html`. 링크 제목과 설명은 `locales/ko.json`, `locales/en.json`에서 관리합니다.
- 개념 지도 본문은 한국어이며, 시기별 펼침·접기와 원 논문·공식 문서 링크를 제공합니다.

## 이력 추가하기

`teaching`의 한 레코드는 기관·과정·역할 ID와 기간만 참조합니다. `end: null`은 현재 활동이며, 시작일과 종료일이 같으면 단일 기간으로 표시합니다. 날짜는 `2026` 또는 `2026-08` 형식을 사용합니다. 기존 과정의 여러 업체 이력은 같은 과정 ID를 참조하는 별도 레코드로 추가합니다.

학위와 자격은 서로 다른 배열입니다. 학위의 `field`가 전공, `degree`가 전체 학위명, `degreeShort`가 모바일 요약용 표기이며, `institution`은 학교명, `school`은 소속 단위를 포함한 정식 표기입니다.

항목 개수, 표시 연도 범위, 현재/이전 구분, 모바일의 최신 항목은 데이터에서 계산합니다. 번역 파일에 숫자나 이력을 복사할 필요가 없습니다. 번역은 일반 텍스트이며 필요한 줄바꿈에는 `\n`을 사용합니다. 논문 제목·저자는 영문, 학회명은 선택 언어에 맞춰 표시하고 BibTeX는 영문을 사용합니다.

### 현재 활동

`currentRoles`는 확인된 현재 역할만 모은 홈·CV의 별도 요약입니다. 연결된 교육 활동이 있는 역할은 `teaching` ID를 참조해 기관·시작월·종료월을 재사용하며, 엘리스 프리랜서 활동처럼 개별 과정과 기간이 다른 역할은 별도 기간을 기록합니다. `title`은 역할, 선택 항목 `context`는 과정 맥락이며 한·영을 함께 적습니다. 종료월(`end`)이 생긴 역할은 현재 활동 영역에서 자동으로 제외됩니다. 종료 예정월은 공유 원본의 `plannedEnd`에 기록하며, `end: null`을 유지해 진행 중으로 표시합니다. 현재 활동 요약은 예정 종료월까지의 기간만 표시하며, 세부 교육 경력은 종료 예정 안내를 유지합니다. 진행 중 상태와 예정 종료월은 공통 원본에서 보존합니다. 프리랜서 활동을 상근·연속 고용으로 표시하지 않고, 과정 수나 전체 경력 수에도 더하지 않습니다. 현재 활동은 모바일에서도 접지 않고 표시하며 기존 분야별 강의·개발 이력은 그대로 유지합니다.

### 사업·과정 중심 교육 이력

교육 이력은 홈·이력·CV 모두 `기간 | 기관·사업명 | 역할·과정` 세 열로 표시합니다. 기본 열 비율은 19:23:58이며, 가운데 열은 사업명을 강조하고 기관을 보조 정보로 표시합니다. 오른쪽 열은 실제 과정명을 강조하고 역할·담당 내용·학교를 함께 표시합니다. 모바일에서는 열을 세로로 쌓고 각 열 이름과 접근성 표 구조를 유지합니다. 별도 사업명이 확인된 과정만 `courses[].program`을 기록하며, 사업명이 없으면 실제 과정명을 제목으로 사용합니다. 사업명이 같아도 기관·원본 사업 ID가 다르면 합치지 않습니다. 검증된 짧은 담당 내용은 `teaching[].summary`를 통해 홈·이력·CV에 함께 반영합니다.

### 학교·업체별 상세 이력

학교별 프로그램명이 확인된 과정은 `courses`의 `showSchoolPrograms`와 `family`, 상세 항목의 `programTitle`을 사용합니다. 웹은 기존 학교 항목에서 실제 프로그램명과 기간을 표시하고, CV는 기관·사업별로 실제 교육과 학교들을 묶어 학교명과 전체 사업 기간만 표시하고 학교별 기간은 생략합니다. 학교별 날짜는 공통 원본과 이력 탭에 그대로 보존합니다. 원본 사업·학교 항목이나 전체 경력 수는 늘리지 않습니다.

기존 `teaching` 항목의 `details` 배열에 학교·업체(`title`), 활동월(`start`, `end`), 역할 ID(`role`), 커리큘럼(`curriculum`)을 기록합니다. 경력 탭에서 각 사업 제목 옆 `+` 버튼으로 세부 이력을 펼칩니다. 다시 누르면 `−`에서 `+`로 돌아오며 접힙니다. 키보드 Enter·Space도 지원합니다. 홈과 PDF는 분야별 과정과 해당 학교를 요약합니다. `note`는 선택 항목입니다. 사업에 속하지 않는 개발·프로젝트 경력은 `otherExperience`에 별도로 기록합니다. `group: "activities"`인 해커톤·42서울·구름 K-Digital 수료는 기타 활동으로 분리합니다. 테드의 프론트엔드 개발과 만렙게임즈의 게임기획은 경력 항목에 모으며, 각 역할과 기간은 구분해 유지합니다. 내부 기본 분류 ID인 `development`는 경력 제목으로 표시합니다. 홈·경력 탭·CV가 같은 분류를 사용합니다.

`teachingGroups`는 인공지능·데이터 교육, 프로그래밍·자료구조·알고리즘 교육 순서이며, `otherExperience`는 경력과 기타 활동으로 나누어 표시합니다. 홈·경력 탭·한영 CV는 같은 분류를 사용합니다. 자료구조는 프로그래밍 분야에 포함하고, 코디세이의 AI Native 과정은 인공지능·데이터 교육으로 표시합니다. AI와 데이터의 원본 주제 분류는 유지하며, 같은 사업·학교의 두 분야는 한 항목 안에서 각 과정명과 내용을 보존합니다.

디지털새싹과 엘리스 SW동행은 `courses`의 `classifyDetails` 및 학교별 `details[].group`을 사용합니다. 실제 내용이 확인된 복수 분야 과정은 `details[].tracks`로 나눕니다. 원본 사업·학교 이력은 한 번만 저장하고 `teaching_records(group)`이 분야별 화면을 만듭니다. 각 화면에 사업명·기관·학교를 남깁니다. 전체 경력 수는 원본 사업과 개발 경력의 고유 개수이며, 분야별 표시 수를 합산하지 않습니다.

한 학교의 여러 트랙에서 `start`·`end`를 생략하면 확인된 학교 전체 활동기간을 표시하며, 트랙별 실시월 미확인 안내를 붙입니다. 확인되지 않은 기간·시수는 만들지 않습니다. `group: null`인 상세는 임의 분류하지 않고 확인 대기 영역으로 보존합니다. 공개 데이터에는 계약서·계좌·학생 정보나 비공개 증빙 링크를 넣지 않습니다.

확인된 활동월만 사용하고 월이 불명확하면 연도만 적습니다. 배정·제안만 확인된 활동이나 비공개 증빙 링크는 공개 데이터에 포함하지 않습니다.

## 생성과 점검

웹 생성에는 Python 표준 라이브러리만 있으면 됩니다. 펼침·접힘 UI 회귀 테스트에는 Node.js를 사용합니다.

```sh
python3 scripts/build.py --site-only
python3 -m unittest discover -s tests
node tests/test_ui.js
```

CV까지 함께 갱신하려면 `reportlab`을 설치하고 `NanumGothic-Regular.ttf`, `NanumGothic-Bold.ttf`, `NanumMyeongjo-Bold.ttf`가 있는 폴더를 지정합니다.

```sh
python3 -m pip install -r requirements.txt
CV_FONT_DIR=/path/to/fonts python3 scripts/build.py
```

CV는 본문 10pt·보조 정보 9pt를 기준으로 하며, 현재 활동과 학위·자격을 병기합니다. 교육 이력은 레코드 단위로 자연스럽게 다음 쪽으로 이어지고 열 머리글을 반복합니다. 개요·연구활동 다음에 교육 경력을 새 쪽에서 시작합니다. 교육 분야를 중간에 자르지 않고 다음 쪽으로 넘기며 이어지는 쪽에는 교육 경력의 계속 표시를 붙입니다. 경력·기타 활동은 앞 내용의 남은 공간을 사용하되 각 제목과 항목 묶음을 함께 유지합니다. 현재 한글·영문 모두 3쪽입니다. 교육 표는 제목·열 머리글·첫 항목이 함께 놓이고, 경력·기타 활동은 각 영역이 함께 유지됩니다. 쪽 수보다 가독성과 내용 보존을 우선합니다. 이름·큰 제목은 NanumMyeongjo Bold, 본문은 NanumGothic Regular/Bold를 사용하며 한글·영문 글꼴을 PDF에 직접 내장합니다. 모두 정적 TrueType 파일이며 글꼴 라이선스를 함께 보관합니다. 공식 배포 원본: [Nanum Myeongjo](https://github.com/google/fonts/tree/main/ofl/nanummyeongjo), [Nanum Gothic](https://github.com/google/fonts/tree/main/ofl/nanumgothic). 이메일과 `profile.portfolioUrl`은 클릭 가능한 연락처로 표시합니다. 확인된 `papers[].authorRole: "first"`는 본인 이름 옆에 제1저자 표기를 추가하며 인용문과 전체 저자 순서는 바꾸지 않습니다.

기본 PDF 출력 위치는 `assets/`입니다. `CV_OUTPUT_DIR`로 다른 폴더를 지정할 수 있습니다. 생성 결과가 같으면 파일을 다시 쓰지 않으며 PDF 생성 시각 때문에 불필요한 변경이 생기지 않습니다. 데이터 수정 후에는 원본과 생성된 HTML·PDF를 함께 커밋합니다.

`scripts/layout-check.html`은 실제 사이트를 320·375·430px 프레임에서 확인하는 개발용 페이지입니다. 검색 제외(`noindex`) 상태이며 사이트 메뉴에 노출되지 않습니다.

웹과 PDF는 `data/design.json`의 디자인 값을 함께 사용합니다. 사용자가 선택한 기준 색상은 `identityPalette`에 보존합니다. 현재 배경은 옅은 베이지·민트 톤으로 조절하고 본문은 차콜, 제목·강조는 네이비로 표시합니다. 작은 글자도 충분한 대비의 짙은 색을 사용합니다. 최종 브랜드 색상이나 질감으로 확정한 것은 아닙니다. `tests/test_design.py`에서 글자 대비, 기본 크기, 열 비율, 표 구조와 반응형 규칙을 점검합니다. 연구 태그는 산세리프 글꼴과 둥근 테두리를 사용합니다. PDF는 실제 글자 폭과 안쪽 여백을 계산해 내용 폭 안에서 줄바꿈하며, 웹도 최대 너비와 긴 단어 줄바꿈을 적용합니다.

## 코드 구성

- `scripts/content.py`: 공통 조회·날짜·인용·검증 규칙
- `data/design.json`, `scripts/design.py`: 웹·PDF 공통 디자인 값과 CSS 변수 생성
- `scripts/html_components.py`: 번역 쌍, 접기 영역, 링크 등 공통 HTML
- `scripts/site_sections.py`, `scripts/publications.py`: 영역별 화면 구성
- `scripts/build_site.py`, `scripts/build_cv.py`: 웹/PDF 출력
- `scripts/build.py`: 전체 생성 명령
- `assets/site.js`: 탭, 접기, 인용, 언어 전환을 각각 독립된 초기화 함수로 구성

언어를 추가할 때는 `languages`에 코드·이름·국기 경로를 넣고 같은 키를 가진 번역 파일과 데이터 번역을 추가합니다. 언어 전환, 접근성 안내, CV 연결은 이 설정에서 생성되므로 JavaScript에 언어별 조건문을 추가할 필요가 없습니다.


구름 K-Digital Training 자연어 처리 과정 수료는 기타 활동에 한 번만 표시합니다. 확인된 연도인 `2022`를 사용하며, 서로 맞지 않는 월 단위 자료에서 정확한 시작·종료월을 추정하지 않습니다.

외주 개발은 확인된 작업기간을 표시하고 계약기간·출시 완료로 확대하지 않습니다. 졸업프로젝트 KimAnNa는 확인된 2018년 활동만 표시하며, 검증되지 않은 전체 시작·종료월이나 팀장 역할을 추정하지 않습니다. 선택적인 `otherExperience[].url`은 HOME·이력·CV에서 프로젝트 제목 링크로 사용합니다.

경력의 역할·기간만 확인된 경우 `description`을 생략할 수 있습니다. 추가 설명이 없는 항목에는 빈 펼침 버튼을 만들지 않습니다.

확인된 학교별 실제 수업명은 `details[].programTitles` 또는 트랙의 `programTitles`에 기록합니다. `school_program_groups`가 동일한 수업명과 학교를 묶어 홈·이력·CV에 공통 표시합니다. 일부 기간에만 확인된 수업명은 `verifiedTeachingStart`·`verifiedTeachingEnd`로 범위를 보존하고 상세 이력에서만 표시합니다. CV에는 학교별 기간을 출력하지 않습니다. 정식 수업명이 확인되지 않은 학교에는 다른 학교의 수업명을 빌려 붙이지 않습니다.
